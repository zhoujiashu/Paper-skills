# zhuanli —— 专利撰写工作流

从"技术成果"产出一份"权利要求保护范围清楚、说明书充分公开且支持权利要求、版式与既有专利稿一致、公式可批量转 MathType"的专利申请文件。

**与 ruanzhu 的关键区别**：软著说明书描述"软件怎么实现"，专利说明书要"公开到本领域技术人员能实施"，权利要求书要"主张保护范围"。同一成果先写软著再改专利时不能照搬——软著里的实现细节应下沉到具体实施方式，权利要求只保留必要技术特征。

## 工作流总览（六步）

0. **路由**：判断输入模式与专利类型（发明/实用新型）
1. **定版式**：默认国知局标准格式（无需模板）；只有需要复刻既有专利稿时才解析模板 docx
2. **提炼**：把输入转成"技术问题—技术方案—技术效果"三段式，圈定创新点
3. **撰写**：**先写权利要求**（确定保护范围），再写说明书（逐项支撑权利要求）
4. **审计**：权利要求 ↔ 说明书 ↔ 证据（代码/实验/交底书）逐项对齐
5. **生成**：写 `content.txt` + 调 `scripts/build_patent_docx.ps1` → 分件 docx
6. **交接**：MathType 公式、附图、请求书、检索自查

## 第零步：输入模式路由

| 模式 | 输入 | 处理要点 |
|---|---|---|
| A 代码 + 技术方案 | 源码、算法说明 | 抽取技术特征；代码↔文稿审计同 ruanzhu；**实现细节不进独立权利要求**，下沉到实施方式 |
| B 技术交底书 | 发明人 md/docx | 补全"问题—方案—效果"；口语、宣传语、内部代号改为规范表述；确认实施例数据可用 |
| C 论文/报告/软著稿 | 已有文稿 | 识别新颖点；删除已公开内容的直接复制；**提示公开在先风险**（论文发表日早于申请日会破坏新颖性） |
| D 纯想法/口述 | 对话 | 先做可实施性检查；缺少结构、参数或实施例时明确要求补充，不要编造 |

**专利类型判定**：方法、算法、工艺、软件流程 → 发明；产品的形状/构造/结合 → 实用新型（也可同时报发明）。实用新型**不得**有方法权利要求，必须有附图。

## 第一步：确定版式（标准格式优先）

### 默认：国知局标准提交格式（不需要模板）

`build_patent_docx.ps1` 不传 `-Template` 时，从零构建符合《专利审查指南》格式要求的 docx 包：

| 要素 | 标准值 |
|---|---|
| 纸张 | A4（11906×16838 twips），单面 |
| 页边距 | 上 25mm、下 15mm、左 25mm、右 15mm |
| 字体 | 中文宋体，西文 Times New Roman，公式 Cambria Math |
| 字号 | 正文/标题/权利要求均为小四 12pt（字高约 4.2mm，处于 3.5–4.5mm 区间） |
| 行距 | 1.5 倍（line=360 auto） |
| 段落 | 正文首行缩进 2 字符、两端对齐；标题与权利要求不缩进 |
| 页码 | 页脚居中、阿拉伯数字、每份文件从 1 连续编号；无页眉 |
| 分件 | 说明书、权利要求书分别成文件（CPC 分件提交） |

标题（发明名称）与章节名用同字号加粗区分，不放大字号，避免超出字高上限。

### 可选：复刻既有专利稿版式

只有用户明确要求"和这份 patent word 一样"时才用模板。先解析模板：

```powershell
powershell -ExecutionPolicy Bypass -File <skill>\scripts\inspect_docx.ps1 -Path "C:\path\专利模板.docx"
```

输出包内条目、根标签、`sectPr`、docDefaults、样式表、numbering、正文样式用量。重点核对 sectPr 页边距与 Normal 字体字号；与上表不一致时以模板为准，并在交付时说明。

## 第二步：说明书撰写规范

### 结构（两类型共用五部分，顺序固定）

```
发明名称（居中，与请求书一致，一般不超过 25 字）
技术领域
背景技术
发明内容
附图说明
具体实施方式
```

### 各部分要求

| 部分 | 要求 |
|---|---|
| 技术领域 | 一句话：本发明/本实用新型涉及……技术领域，具体涉及一种……。不写"所属技术领域为……"式套话堆砌 |
| 背景技术 | 客观描述最接近的现有技术方案及其不足；可引证专利/文献；**只评价技术缺陷，不贬损他人、不写商业宣传**；不得出现"本发明" |
| 发明内容 | 三段式：①要解决的技术问题 ②技术方案（**与权利要求 1 逐字对应**）③有益效果（与背景技术的缺陷一一对应，可给数据） |
| 附图说明 | 逐条："图1为……示意图；图2为……流程图。" 附图标记在具体实施方式首次出现时解释 |
| 具体实施方式 | 至少一个完整实施例；公开到本领域技术人员可实现；参数给范围+端点+中间值；结尾写"以上所述仅为本发明的较佳实施例……" |

### 发明 vs 实用新型

| 项 | 发明 | 实用新型 |
|---|---|---|
| 保护对象 | 产品、方法、改进 | 仅产品形状/构造/结合 |
| 方法权利要求 | 允许 | **禁止** |
| 材料/配方权利要求 | 允许 | 一般不允许（仅结合形状构造时） |
| 附图 | 建议有 | **必须有** |
| 创造性高度 | 突出实质性特点+显著进步 | 实质性特点+进步 |
| 说明书侧重 | 原理、步骤、参数推导 | 结构、连接关系、装配、工作过程 |

## 第三步：权利要求书撰写规范（核心）

### 独立权利要求

```
1. 一种<主题名称>，其特征在于，包括：<必要技术特征 A>；<必要技术特征 B>；……
```

- 前序部分 = 主题名称 + 与最接近现有技术共有的必要技术特征；特征部分以"其特征在于"引出区别技术特征
- **必要技术特征取最小完备集**：少一个方案不成立，多一个白白缩小保护范围
- 一件申请可有多项独立权利要求（方法/系统/设备/存储介质），但须满足单一性
- 方法权利要求用步骤 S1/S2…；产品权利要求用部件+连接关系，不写"用于……"的纯功能模块堆砌

### 从属权利要求

```
2. 根据权利要求1所述的<主题名称>，其特征在于，<进一步限定或附加技术特征>。
```

- 引用在前的权利要求，编号连续；多项从属只能**择一**引用（"根据权利要求1或2所述"），且不得作为另一项多项从属的引用基础
- 层次设计：从宽到窄，每层增加一个可独立主张的限定；不要把所有细节堆进权利要求 2

### 硬规则（违反即驳回风险）

- [ ] 每个"所述 X"必须在前文有引用基础；首次出现用"一个/一种 X"
- [ ] 权利要求中不得出现"如说明书……所述""如图所示""例如""最好是""尤其是""必要时"
- [ ] 不得用商标、人名、地名、型号指代技术特征（应描述其结构/参数）
- [ ] 不得纯功能限定（除非本领域技术人员能直接确定实现方式）
- [ ] 权利要求书不得有附图、不得引用附图标记作为限定
- [ ] 每项权利要求以句号结尾，一项一个自然段
- [ ] 独立权利要求与说明书"发明内容—技术方案"段逐字一致

## 第四步：内容↔证据审计（核心价值）

输出 ✅/❌ 对应表，逐项核对：

- [ ] 权利要求 1 的每个技术特征 ↔ 说明书具体实施方式有对应文字或附图（专利法 26.4 支持）
- [ ] 每条从属权利要求的附加特征 ↔ 说明书有记载
- [ ] 说明书公开充分性：本领域技术人员按文稿能复现（26.3），关键参数/步骤无缺口
- [ ] 背景技术描述的现有技术 ↔ 交底书/检索到的真实方案，不虚构对比文件
- [ ] 有益效果的数字 ↔ 实测/仿真/代码运行结果，注明测试条件
- [ ] 术语全文统一（"控制器"与"控制单元"不混用）
- [ ] 附图标记全文一致（图1 中 1-机架、2-转轴 ↔ 文字）
- [ ] 数值范围与单位 ↔ 代码常量/实验记录（GUI 显示单位 × 换算系数 = 内部单位）
- [ ] 权利要求引用关系合法（无循环、无多项从属引用多项从属）
- [ ] 实用新型无方法权利要求、有附图
- [ ] 摘要（若生成）≤300 字，无商业宣传用语
- [ ] 无"最优/最佳/完全/彻底/100%"等绝对化用语

## 第五步：DSL → docx（模板包替换法）

**两种模式**：默认从零构建标准 docx 包（document/styles/settings/footer + PAGE 域）；传 `-Template` 时改为复制模板、只替换 `word/document.xml` 与 `core.xml`，样式/页眉页脚全部继承。`DOC|` 切换分件，默认**每份文档输出一个 docx**（国知局 CPC 要求说明书、权利要求书分件提交）。

### 内容 DSL（UTF-8，`|` 分隔，行首标签，脚本纯 ASCII）

```
DOC|说明书                 开始一份文档（名称即输出文件名）
DOC|说明书摘要             可选：摘要正文 ≤300 字，脚本自动计数告警
TITLE|一种xxx方法          发明名称：居中加粗 sz24（12pt）
SEC|技术领域               章节名：加粗、无首行缩进、段前段后 6pt
B|正文段落                 首行缩进 2 字符、1.5 倍行距、两端对齐
BQ|无缩进正文              权利要求/公式解释等无缩进段
CLAIM|1. 一种……            权利要求项：无首行缩进、两端对齐
EQN|(1)|latex              公式：居中制表位 + 灰色斜体 LaTeX + 右侧编号；可省略编号
FIG|图1 xx示意图           空居中段（贴图占位）+ 居中题注 sz21
TCAP|表1 xx参数            表题（居中 sz21）
TBLH|a##b##c               表头行；TBLR|.. 数据行；列数按本表最大列数自适应
PAGEBREAK                  分页
REFH|参考文献              加粗章节标题
REF|1. ...                 参考文献 sz21 左对齐
```

行内标记：`[i]..[/i]` 斜体、`[sb]..[/sb]` 下标、`[sp]..[/sp]` 上标、`[b]..[/b]` 加粗。LaTeX 行内不得含 `|` 字符。

### 调用

默认标准格式（不传 `-Template`）：

```powershell
powershell -ExecutionPolicy Bypass -File <skill>\scripts\build_patent_docx.ps1 `
  -Content "C:\path\content.txt" -OutDir "C:\path\out" -BaseName "一种xxx方法"
```

需要复刻既有专利稿时加模板：

```powershell
powershell -ExecutionPolicy Bypass -File <skill>\scripts\build_patent_docx.ps1 `
  -Template "C:\path\专利模板.docx" -Content "C:\path\content.txt" `
  -OutDir "C:\path\out" -BaseName "一种xxx方法"
```

- `-SingleFile`：把 `DOC|` 各节合并为一个 docx（分页分隔）
- `-SkipValidation`：跳过 Word COM 试开验证
- 脚本自动：构建正文 XML → `[xml]` 良构校验 → 标准模式写出 document/styles/settings/footer（或模板模式替换 `document.xml`）→ 摘要字数检查 → Word 试开验证

## 关键坑位速查

| 坑 | 规则 |
|---|---|
| PowerShell .ps1 含中文 | **脚本必须纯 ASCII**；中文一律放 UTF-8 内容文件，或用 `[char]0xXXXX` |
| Word COM 设样式 | 中文版 Word 下英文样式名报"项不存在"；直接 XML 构建，不靠 COM 设样式 |
| 权利要求写成说明书 | 权利要求只写"是什么/怎么构成"，不写原理推导和实验数据 |
| 独立权利要求过窄 | 把实施例细节写进权利要求 1 会让保护范围形同虚设；细节下沉从属项 |
| 照搬论文/软著 | 已公开文本直接复制可能构成自我公开；且论文语言不是权利要求语言 |
| MathType 占位 | 禁用 `aligned`/`cases` 等 amsmath 环境，用 `\begin{array}{l}`；无 `$` 定界符 |
| 三线表 | 专利表格不要求三线表；脚本用细网格线，居中 sz21 |
| 版式超限 | 标题不要用三号/四号放大：全文小四 12pt（字高约 4.2mm）才落在 3.5–4.5mm 区间 |
| 页码/页眉 | 标准模式已写入页脚居中 PAGE 域、无页眉；模板模式以模板为准 |
| 摘要 | ≤300 字；`DOC|说明书摘要` 会触发脚本计数，超限输出 WARNING |
| 附图 | 附图不属于说明书文字部分，应单独成页/单独文件；本脚本 FIG 仅占位，实用新型不得缺图 |
| 输出被占用 | Word 开着目标文件时写包报 IOException；提示关闭后重试 |
| 请求书 | 本 skill 不生成请求书（申请人/发明人/地址/代理信息需在 CPC 或请求书模板填） |

## 交付话术

生成后告知用户：
1. 生成了哪些 docx（说明书 / 权利要求书 / 摘要），已按国知局标准版式排版（A4、25/15/25/15mm、宋体小四、1.5 倍行距、页脚居中页码）
2. N 条公式为灰色 LaTeX 占位 → MathType Toggle TeX（Alt+\）逐条转换
3. M 处附图占位 → 插入图片；实用新型必须补齐附图
4. 提交前人工确认：申请人/发明人/地址、是否要求提前公开、是否请求实质审查
5. 本 skill 不替代专利代理师与检索报告；建议申请前做新颖性自查
